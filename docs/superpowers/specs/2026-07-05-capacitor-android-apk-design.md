# Capacitor Android APK Design

## Goal

Build an installable Android APK for the offline cdda-guide fork. The APK should
open directly from the Android launcher and include the built web app plus
bundled offline JSON data. The first milestone is a debug APK that can be
sideloaded for testing.

## Non-Goals

- Do not publish to the Play Store in this milestone.
- Do not set up release signing in this milestone.
- Do not add GitHub Release automation in this milestone.
- Do not bundle tileset image packs.
- Do not replace the web app architecture with native Android UI.

## Approach

Use Capacitor as a thin Android WebView shell around the existing Vite app. The
web app remains the source of truth. The Android project consumes the generated
`dist/` directory from `npm run build:offline`.

This fits the offline goal better than a Trusted Web Activity because the APK can
carry the built web assets and bundled JSON data. It does not require GitHub
Pages, a custom domain, or Digital Asset Links before users can open the app.

## App Identity

- App name: `CDDA Guide`
- Android package/application id: `io.github.godrenech.cddaguide`
- Web output directory: `dist`

The package id can be changed before a release build if needed, but changing it
after users install a release would create a different Android app.

## Dependencies

Add Capacitor packages:

- `@capacitor/core`
- `@capacitor/cli`
- `@capacitor/android`

Use the current compatible Capacitor version resolved by npm at implementation
time. The Android project generated by Capacitor should be committed because it
contains the Gradle wrapper and native project files required to build the APK.

## Build Flow

Add scripts:

- `android:sync`: run `npm run build:offline` and sync `dist/` into Android.
- `android:debug`: run the sync step, then build a debug APK.

The expected debug APK output is:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

The debug APK is suitable for sideload testing. Android may warn that it is a
debug build; that is acceptable for this milestone.

## Offline Behavior

The APK serves the generated web assets from Capacitor's local app server. The
existing app should still load:

- `offline-manifest.json`
- bundled `all.json`
- bundled `zh_CN.json`
- bundled `zh_CN_pinyin.json`, when generated

The web app already supports downloading additional versions through remote
requests. In the Android APK, this remains an optional online action. The default
two bundled versions should work without GitHub Pages.

## Android Project Policy

Commit the generated `android/` project so future builds do not depend on a
developer manually re-running `cap add android` from scratch.

Do not commit generated APK files. Ignore Android build outputs such as:

- `android/app/build/`
- `android/.gradle/`
- `android/build/`

Keep `dist/` ignored as it is already generated output.

## Verification

Verify with:

```shell
npm run build:offline
npx cap sync android
android/gradlew assembleDebug
```

On Windows, the final command may be run as:

```shell
.\android\gradlew.bat assembleDebug
```

If Android SDK or Java tooling is missing, document the exact missing dependency
and keep the web/Capacitor project changes committed.

## Follow-Up Work

After the debug APK works, a later milestone can add:

- release signing configuration
- GitHub Actions APK build
- GitHub Release upload
- versioned APK naming
- optional Android icons/splash screen polish
